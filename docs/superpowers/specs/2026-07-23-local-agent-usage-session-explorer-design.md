# 本地 Agent 用量分析与会话回溯设计

## 1. 背景

agent-usage-desktop 当前可以从 Claude Code、Codex、OpenClaw、OpenCode 等本地数据源采集 token 与费用，并提供用量总览和会话聚合列表。

项目近期加入了 Provider、MCP、Skills、配置同步和备份等配置管理能力。这些能力已经形成独立子产品，与 CC Switch 等成熟配置工具高度重叠，且需要持续跟进不同 Agent 的配置格式、安装方式和兼容变化，不符合本项目最有优势的数据采集与分析方向。

另一方面，当前会话详情只按模型聚合调用次数、token 和费用。用户若想回顾一次会话中聊了什么、调用了哪些工具、工具返回了什么，仍然需要自己定位并阅读 JSONL 或 Agent 数据库。

因此，产品重新定位为：

> 本机多 Agent 用量分析与会话回溯工具。

产品只服务当前电脑的个人用户，不扩展为配置切换工具、团队管理平台或 Agent 运行环境。

## 2. 要解决的问题

1. 用户难以在一个界面中看清本机不同 Agent、模型和项目消耗了多少 token 与费用。
2. 当前总览缺少清晰的信息层级，核心结论、趋势和明细之间的关系不够明确。
3. 当前会话页只有聚合统计，无法直接阅读用户消息、模型回复、工具调用、工具结果和错误。
4. 不同 Agent 使用不同的本地存储格式，用户需要手工寻找和理解 JSONL 或 SQLite 数据。
5. 本地日志不一定包含实际网络请求的全部内容，产品必须区分“日志中可见的数据”和“完整请求 payload”，避免误导。
6. 配置管理能力与成熟产品重叠，继续投入会分散维护资源并模糊产品定位。

## 3. 产品目标

1. 用户可以在总览页快速回答：用了多少、主要花在哪个 Agent 和模型、最近趋势怎样。
2. 用户可以按 Agent、项目、模型、日期和内容查找本机会话。
3. 用户可以通过可读时间线回顾一次会话中的消息、工具调用、工具结果和错误。
4. 用户可以从标准化事件定位并查看对应的原始 JSONL 记录或数据库行。
5. 产品明确展示每个数据源的可回溯覆盖程度和异常状态。
6. 所有会话解析、索引、搜索和统计默认只在本机完成。
7. 首期将 Claude Code 与 Codex 做深，并保留可扩展的数据源适配边界。

## 4. 非目标

首期不做：

- Provider、账号或模型配置切换。
- MCP、Skills、配置同步或配置备份管理。
- 团队、组织、账号、权限或成员统计。
- 云同步、远程上传或在线分享服务。
- 内置聊天、终端、会话恢复或 Agent 执行能力。
- Agent 之间的会话交接与任务编排。
- 网络代理或 HTTP payload 抓包。
- OpenCode、OpenClaw、Hermes 的深度会话回溯。
- PNG、PDF 和分享型 BI 报告。
- 最终字体、颜色、图标、图表样式和品牌视觉定稿。

## 5. 用户角色与数据边界

| 角色 | 说明 | 可执行操作 |
| --- | --- | --- |
| 本机用户 | 当前电脑的唯一使用者 | 查看本机统计、搜索会话、阅读时间线、查看原始记录、调整应用自身设置 |

产品没有管理员、团队负责人或其他远程用户角色。

所有页面和接口仅绑定本机 loopback 地址。会话正文、工具参数和工具结果不得由应用主动上传。

## 6. 版本范围

### 6.1 首期

- Claude Code 深度统计与会话回溯。
- Codex 深度统计与会话回溯。
- 用量总览。
- 会话列表、筛选与全文搜索。
- 可读会话时间线。
- 按需事件检查器与原始记录查看。
- 应用自身设置。
- 数据完整度、解析异常、源文件缺失和未知价格状态。

### 6.2 后续数据源

按以下默认顺序扩展，实际顺序可以根据用户反馈调整：

1. OpenCode。
2. OpenClaw。
3. Hermes。

每个新增来源必须通过统一会话适配接口接入，不能为单一来源修改公共页面契约。

### 6.3 后续分享能力

在核心统计与回溯稳定后增加：

- 日、周、月和自定义时间范围的分享型 BI 页面。
- PNG 与 PDF 导出。
- 导出前预览和隐私字段检查。
- 默认不包含提示词、模型回复、工具参数、本地路径或会话正文。
- 固定展示项目名称、GitHub 项目地址和 linux.do 论坛链接。
- 可选展示项目二维码。

分享能力是推广入口，不是首期核心使用流程。

## 7. 核心对象

### 7.1 Agent 来源

表示 Claude Code、Codex 等本地 Agent 数据源，包含：

- 来源标识。
- 默认与用户覆盖后的扫描路径。
- 是否可用。
- 最后扫描时间。
- 可回溯能力声明。
- 当前错误或警告。

### 7.2 会话

表示一次 Agent 会话，包含：

- 来源和会话 ID。
- 项目、工作目录和 Git 分支。
- 开始时间、结束时间或最后活动时间。
- 模型集合。
- 用户消息数、工具调用数和错误数。
- token 与费用聚合。
- 来源定位信息。
- 回溯覆盖状态。

### 7.3 标准会话事件

不同来源统一为以下事件类别：

- `user_message`：用户消息。
- `assistant_message`：模型回复。
- `reasoning`：来源明确记录的思考或推理内容。
- `tool_call`：工具名称和调用参数。
- `tool_result`：工具返回内容与执行状态。
- `error`：模型、工具或解析错误。
- `metadata`：模型切换、上下文压缩等会话元信息。
- `unknown`：暂时无法标准化但仍可查看的原始事件。

事件包含标准化展示字段和原始定位信息。产品不得根据不完整日志推测未记录的系统提示词、工具 Schema 或隐藏上下文。

### 7.4 用量记录

继续沿用现有非重叠 token 语义：

```text
total_input = input_tokens
            + cache_read_input_tokens
            + cache_creation_input_tokens

total_output = output_tokens
total_tokens = total_input + total_output
```

`reasoning_output_tokens` 是 `output_tokens` 的信息性子集，不重复计入总量。

## 8. 数据架构

### 8.1 数据流

```text
本地 JSONL / SQLite
        -> Agent 会话适配器
        -> 标准会话事件与用量记录
        -> SQLite 元数据、事件索引和全文搜索
        -> REST API
        -> 总览、会话列表、时间线和事件检查器
```

### 8.2 Agent 会话适配器

每种 Agent 独立实现适配器，负责：

- 发现会话及其原始来源。
- 增量读取新事件。
- 解析标准会话事件。
- 提取 token、模型、项目和时间等元数据。
- 根据原始定位读取单条原始记录。
- 声明自身支持的事件与内容覆盖能力。

公共页面和 API 只依赖标准事件，不直接理解各 Agent 的私有日志结构。

### 8.3 SQLite 索引

SQLite 需要保存：

- 会话来源定位、文件状态、解析器版本和可回溯能力。
- 标准化事件正文、事件类型、时间和工具信息。
- 事件对应的文件偏移量、行号或数据库行标识。
- 用于本地全文搜索的事件文本索引。

原始 JSON payload 不重复保存。用户打开原始记录时，应用根据定位信息从事实来源按需读取。

### 8.4 事实来源与历史数据

- 原始 JSONL 或 Agent 数据库是会话内容的事实来源。
- SQLite 中的标准事件与全文搜索是可重建索引。
- JSONL 追加时只解析新增内容。
- 文件被截断、替换或解析器版本变化时重建对应会话索引。
- 原始来源消失时，保留 token 统计和会话元信息，清除正文索引，并标记“原始记录已不可用”。
- 用户可以清理会话正文索引而不删除用量统计。
- 原始来源恢复后可以重新构建会话索引。

## 9. 页面信息架构

首期主导航只有：

1. 总览。
2. 会话。
3. 设置。

项目提供的 agent-usage-desktop Skill 可以继续独立发布和安装，但应用内不再提供通用 Skills 管理中心。

### 9.1 总览

#### 页面目标

按“结论 -> 构成与趋势 -> 明细”的顺序回答本机用量问题。

#### 顶部控制区

- 时间范围：今天、7 天、30 天、自定义。
- Agent 筛选。
- 手动刷新。
- 首次打开默认 7 天，之后记住用户上次选择。
- 显示最后更新时间和当前采集状态。

#### 第一层：核心指标

- 总 token。
- 估算费用。
- 会话数。
- 用户消息数。
- 缓存命中率。

#### 第二层：趋势与构成

- 输入、输出和缓存 token 趋势。
- 各 Agent 的 token、费用、会话数和占比。

#### 第三层：明细

- 模型维度的 token、费用和缓存命中率。
- 项目维度的 token 排名。

总览不展示会话正文。点击 Agent、模型、项目或趋势日期时，进入携带相同筛选条件的会话页。

### 9.2 会话中心

#### 页面布局

- 左侧：约 300-340px 的会话列表，可折叠并允许调整宽度。
- 中间：占据主要空间的会话时间线。
- 右侧：按需展开的事件检查器。
- 小窗口：列表和详情改为两级页面，避免强制多栏压缩。

该布局只确定信息量和空间关系，视觉风格后续单独设计。

#### 会话列表

- 默认按最近活动时间倒序。
- 支持 Agent、项目、模型和时间范围筛选。
- 支持搜索用户消息、模型回复、工具名称、工具参数和工具结果。
- 显示会话标题或首条用户消息摘要、Agent、时间、时长和 token。
- 从总览进入时保留筛选条件，并提供一键清除筛选。

#### 会话头部

- 项目、分支和 Agent。
- 会话标题。
- 开始时间和模型。
- 可回溯覆盖状态。
- 总 token、输入输出、缓存、工具调用数和估算费用。

#### 会话时间线

- 用户消息、模型回复、思考内容、工具调用、工具结果和错误按时间排序。
- 工具调用默认折叠。
- 错误事件默认展开。
- 长代码与长工具输出默认折叠并允许展开。
- 来源没有记录的内容显示“来源未提供”，不能伪造占位内容。

#### 事件检查器

- 点击工具调用、工具结果、错误或“原始记录”后从右侧展开。
- 展示事件类型、来源类型、时间、执行状态、耗时和标准化参数。
- 提供原始 JSON 视图。
- 原始数据按需加载。
- 关闭检查器后，中间时间线恢复为宽阅读区。

### 9.3 设置

只维护应用自身能力：

- 语言。
- 主题。
- 各 Agent 采集启停。
- 扫描路径。
- 扫描频率。
- 价格同步。
- 通知与费用阈值。
- 清理并重建会话索引。

设置页不得演变为 Provider、MCP、Skills 或账号配置中心。

## 10. 页面联动规则

- 总览和会话页共享时间范围与 Agent 筛选语义。
- 点击总览中的 Agent、模型、项目或日期时，进入相应筛选后的会话页。
- 会话页允许清除从总览继承的筛选。
- 用户上次主动选择的时间范围与 Agent 筛选保存在本地偏好中。
- 全文搜索只针对已建立索引的本地会话正文。
- 原始 JSON 只在用户主动请求时读取。

## 11. 覆盖状态与异常处理

| 场景 | 页面状态 | 处理方式 |
| --- | --- | --- |
| 首次采集 | 正在扫描 Agent，并显示已发现会话数 | 分来源展示进度，完成的来源可以先使用 |
| 完整可回溯 | 完整可回溯 | 展示时间线、搜索和原始记录 |
| 部分可回溯 | 部分可回溯，并列出缺失内容 | 展示已有事件，不推测缺失内容 |
| 仅统计 | 仅统计 | 展示 token 与元信息，不展示正文入口 |
| 原始来源缺失 | 原始记录已不可用 | 保留统计与元信息，清除正文索引 |
| 日志存在格式错误 | 已跳过 N 条异常记录 | 保留其余可解析事件，并允许查看错误摘要 |
| 来源格式暂不支持 | 当前版本无法解析该会话 | 不影响其他来源和其他会话 |
| 模型价格未知 | 费用暂不可计算 | token 统计继续可用，价格同步后回填 |
| 扫描路径不存在 | 未找到数据目录 | 展示实际扫描路径，并引导到应用设置 |
| SQLite 索引损坏 | 会话索引需要重建 | 允许重建索引，不删除原始 Agent 数据 |

单个文件、单个会话或单个来源的错误不得阻断其他来源的统计与浏览。

## 12. 隐私与安全

- 后端默认只监听 `127.0.0.1`。
- 会话正文、工具参数、工具结果和本地路径不主动上传。
- 应用不声称还原完整网络请求，只展示本地来源实际记录的内容。
- 分享型导出默认只包含聚合指标。
- 后续导出会话内容时必须要求用户主动选择，并在导出前预览。
- 清理会话索引不删除 Agent 原始文件。
- 应用不得提供删除 Agent 原始会话的功能。

## 13. 配置管理移除与兼容策略

首期实现需要移除：

- 配置管理主导航和前端页面。
- Provider、MCP、Skills、同步和备份相关 REST API。
- 配置管理运行时初始化、文件写入、同步和冲突处理逻辑。
- 对应的不再使用的前端文案和依赖。

兼容策略：

- `usage_records`、`sessions`、`prompt_events`、`pricing`、`file_state` 和现有用量数据保持兼容。
- 应用自身 `config.yaml` 继续使用，用于采集、存储、价格和服务设置。
- 首期不执行破坏性的配置管理删表迁移。
- 已存在的配置管理表作为闲置历史数据保留，应用不再读取或写入。
- 新版本稳定运行后，数据库删表与空间回收作为独立需求评估，不包含在本期。

## 14. 测试策略

### 14.1 适配器测试

- Claude Code 与 Codex 使用固定日志样本验证全部标准事件类型。
- 验证 JSONL 增量追加不会重复建立事件或用量记录。
- 验证文件截断、替换和解析器版本变化会重建对应索引。
- 验证异常行被跳过并正确计数。
- 验证未支持事件保留为 `unknown`，而不是静默丢失。

### 14.2 存储测试

- 标准事件写入与去重。
- 全文搜索覆盖消息、工具名称、参数与结果。
- 清理正文索引不影响用量统计。
- 原始来源缺失后正文索引清理与状态更新。
- 已有数据库升级不丢失历史用量数据。

### 14.3 API 测试

- 时间范围、Agent、模型、项目和关键词筛选。
- 总览到会话页的筛选语义一致。
- 会话详情分页或分段加载。
- 原始事件按需读取。
- 无效日期、缺少会话 ID 和源文件缺失返回明确错误。

### 14.4 前端测试

- 首次扫描、加载、空态、异常态和部分数据状态。
- 会话列表筛选与搜索。
- 时间线事件折叠和错误默认展开。
- 事件检查器打开、切换和关闭。
- 小窗口下列表与详情切换。
- 未知价格不影响 token 展示。

### 14.5 端到端验证

- 使用本地 Claude Code 和 Codex 样本完成一次全量扫描。
- 从总览点击 Agent 或日期进入筛选后的会话页。
- 搜索一条用户消息并打开对应会话。
- 查看工具调用详情和原始 JSON。
- 追加新日志后验证增量刷新。
- 删除样本源文件后验证统计保留、正文清理和状态提示。

## 15. 验收标准

1. 首期产品主导航只有总览、会话和设置。
2. 配置管理相关页面、API 和运行逻辑不再对用户可用。
3. 已有用量数据库升级后，历史 token、费用和会话统计不丢失。
4. Claude Code 与 Codex 都能展示准确的聚合统计。
5. 总览按结论、趋势与构成、模型与项目明细三个层级展示信息。
6. 用户可以从总览中的 Agent、模型、项目或日期进入筛选后的会话列表。
7. 会话详情可以展示来源实际记录的消息、工具调用、工具结果和错误。
8. 用户可以从标准事件查看对应的原始记录。
9. 用户可以搜索用户消息、模型回复、工具名称、参数和结果。
10. 来源缺失、部分可回溯、异常记录和未知价格都有明确状态，不产生误导性数据。
11. 单个来源解析失败不影响其他来源。
12. 会话正文和工具数据默认不离开本机。
13. 页面信息结构符合已确认的总览层级和会话双栏加按需检查器布局。
14. 首期实现不以当前探索稿的配色、字体和图表视觉作为最终设计约束。

## 16. 设计决策摘要

- 产品核心是本机统计与会话回溯，不是 Agent 配置或团队治理。
- 首期选择“Claude Code 与 Codex 做深”，不追求所有来源的浅层覆盖。
- 原始 Agent 数据是事实来源，SQLite 是标准化索引和统计层。
- 会话页面以阅读为主，深度审计按需展开。
- 分享型 BI 是后续推广能力，不抢占首期核心开发资源。
- 视觉风格后续单独设计，本设计只固定信息量、布局、数据和交互边界。
