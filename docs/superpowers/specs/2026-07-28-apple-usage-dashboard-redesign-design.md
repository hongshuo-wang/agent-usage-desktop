# Apple 风格使用分析界面改造设计

日期：2026-07-28  
状态：已确认设计，待规格复核  
范围：使用分析页面、应用导航与全局视觉基线

## 1. 目标

- 让使用者打开页面后先看到 Token 总量，再理解变化发生在何时、由哪些模型和项目构成。
- 结合 macOS 原生工具的克制骨架与轻量洞察工作台的信息层级，兼顾日常扫描效率和产品质感。
- 保留当前新版已经提供的筛选、趋势、排行、吞吐和会话下钻能力，不改变数据语义。
- 降低成本估算的视觉权重，使其成为辅助参考，而不是页面主结论。
- 建立可复用的导航、排版、颜色、间距和状态规范，使后续页面可以沿用同一视觉基线。

## 2. 非目标

- 本轮不统一重做会话记录和系统设置页面的内容结构。
- 不修改后端 REST API、Token 语义、成本计算、采集器或存储结构。
- 不新增历史同期比较接口；没有可靠对比数据时不展示环比数字。
- 不增加关于中转站价格或成本准确性的显式警告。
- 不引入新的 UI 框架、图表库或动画依赖。

## 3. 设计方向

采用“A × C”合并方向：

- 视觉骨架来自 macOS 原生工具：固定导航、系统中性色、紧凑工具栏、克制边界和稳定数据密度。
- 信息层级来自轻量洞察工作台：一个明确主数字、一条可行动洞察，详细趋势与排行向下展开。
- 不使用大面积彩色卡片、渐变背景、装饰性玻璃效果或强阴影。
- 交互强调色使用 Apple 蓝；成功、警告和错误色只表达状态，不作为大面积装饰。

## 4. 页面信息层级

### 4.1 应用导航

- 桌面宽窗口使用左侧导航，包含使用分析、会话记录和系统设置。
- 当前页面使用中性选中底色、清晰文字和图标共同表达，不只依赖颜色。
- 主题和语言等全局动作保留在应用壳层，但不与页面主任务争抢注意力。
- 窄窗口将左侧导航收敛为紧凑顶部导航，主内容保持单一滚动容器。

### 4.2 页面工具栏

- 左侧显示时间范围上下文与“使用分析”标题。
- 右侧保留现有时间范围、Agent、粒度、高级筛选和刷新能力。
- 高频选项直接可见，模型与项目等高级条件按需展开。
- 工具栏控件使用稳定高度和紧凑圆角，数据更新不改变布局尺寸。

### 4.3 Token 主摘要

- Token 总量是首屏唯一主指标，使用最大字号和最高对比度。
- 主指标标签明确写作“Token 总量”，数值使用等宽数字特性。
- 如果现有数据不能可靠提供同期变化，则不显示“较上周”文案。
- 会话、用户消息、缓存服务比例和成本估算排列在辅助指标区。
- 成本估算使用更小字号和较低文字对比度，不增加价格失真提示。

### 4.4 用量洞察

- 洞察使用当前已有数据生成，不新增后端契约。
- 时间序列用于识别当前范围内的最高用量时间点。
- 模型和项目排行用于展示当前范围内的首要构成，不把全周期排行描述为某个峰值的直接原因。
- 洞察提供“查看相关会话”入口，并携带当前时间或维度筛选条件。
- 数据不足时不显示推断性文本，改为直接展示可验证的当前范围摘要。

### 4.5 趋势与排行

- Token 趋势是首个分析区块，保留输入、输出、缓存读取和缓存创建分量。
- 模型用量与项目排行保持可点击，下钻至带筛选条件的会话页面。
- Agent 构成和本地吞吐保留在后续详情区，首屏不与 Token 主趋势竞争。
- 图表使用系统中性色与单一蓝色强调，网格线、坐标轴和图例降低对比度。
- 现有趋势/真实值吞吐模式和高峰标记继续保留。

## 5. 组件边界

### Layout

- 负责桌面左侧导航、窄窗口顶部导航、全局动作和主滚动容器。
- 保持现有路由 `/`、`/sessions` 和 `/settings` 不变。

### DashboardToolbar

- 组合现有 `TimeRangeSelector` 能力并调整呈现顺序。
- 继续通过现有 `UsageFilters` 更新 URL、持久化筛选并触发刷新。

### TokenSummary

- 接收 `DashboardStats`，渲染 Token 主指标和辅助指标。
- 只负责呈现，不自行计算成本或改变 Token 字段含义。

### UsageInsight

- 接收时间序列、模型排行、项目排行和当前筛选。
- 通过纯函数产生可验证的最高点与当前范围摘要。
- 不把缺失数据替换为推测性文案。

### UsageAnalysis

- 组合趋势图、模型排行、项目排行、Agent 构成和吞吐详情。
- 复用现有 ECharts、排行行组件和会话跳转逻辑。

## 6. 数据与交互流程

1. 页面从 URL 和本地偏好恢复 `UsageFilters`。
2. 现有请求并行获取统计、Token 时间序列、Agent/模型/项目排行、吞吐和索引状态。
3. `TokenSummary` 直接消费统计响应；`UsageInsight` 使用纯展示函数从已有响应生成摘要。
4. 用户改变时间、Agent 或高级筛选后，沿用现有请求取消/世代保护逻辑，避免旧响应覆盖新状态。
5. 用户点击日期、模型、项目、Agent 或洞察入口时，沿用 `buildSessionsSearch` 导航到会话页面。
6. 成本值继续使用后端返回的 `total_cost`，仅改变视觉权重。

## 7. 状态设计

### 加载

- 骨架尺寸与最终 Token 摘要、趋势和排行布局一致，避免加载完成后跳动。
- 已有数据刷新时保留当前内容并显示局部进度，不用整页空白覆盖。

### 空状态

- Token 和排行都为空时显示完整空状态，并提供修改时间或 Agent 筛选的入口。
- 单个排行为空时只在对应区块显示轻量空状态，其余成功内容保持可用。

### 错误

- 概览请求完全失败时在主内容区提供重试。
- 吞吐等独立请求失败时只影响对应区块，不覆盖 Token 摘要和趋势。
- 错误使用文案、图标和颜色共同表达，保留键盘可访问的重试按钮。

### 索引状态

- 正常索引状态不占用首屏。
- 确实影响数据完整性时保留现有可操作提示，并链接到系统诊断。

## 8. 响应式与主题

- 宽窗口使用侧栏和双栏分析布局；主趋势宽于排行。
- 中等窗口保留导航但允许分析区折行。
- 窄窗口隐藏侧栏并显示顶部导航，摘要、洞察、趋势和排行全部单栏排列。
- 任何宽度下不出现页面级横向滚动；仅数据表等必要内容允许局部横向滚动。
- 浅色使用接近 macOS 的冷中性背景和白色内容面；深色使用非纯黑背景和分层灰色表面。
- 深浅色都使用同一蓝色语义层级，并满足正文、辅助文字和焦点状态的可读性要求。
- 遵循 `prefers-reduced-motion`，动画只使用短时透明度和位移过渡。

## 9. 测试策略

### 单元与组件测试

- 验证 Token 总量在摘要中的主导顺序，成本估算位于辅助指标区。
- 验证没有可靠同期数据时不渲染环比文案。
- 验证洞察纯函数只使用已有时间序列和排行数据，不错误归因。
- 验证模型、项目、日期和洞察下钻生成正确的会话筛选参数。
- 验证加载、完整空状态、局部空状态、主错误和局部错误。
- 验证桌面导航当前态及窄窗口导航可访问名称。

### 回归与视觉验证

- 运行全部前端测试和 TypeScript/Vite 构建。
- 运行现有 Go 测试，确认前端改造没有契约回归。
- 检查浅色与深色、中文与英文、宽桌面与窄窗口截图。
- 检查文本截断、焦点可见、键盘导航、一个主滚动容器和无页面级横向滚动。

## 10. 验收标准

- 首屏最大、最醒目的数值是 Token 总量，成本估算不占据主视觉。
- 页面能在短时间内回答 Token 用量、最高用量时间、主要模型和主要项目。
- 当前新版的筛选、刷新、图表模式、排行点击和会话下钻行为全部保留。
- 洞察文案只陈述现有数据可以证明的事实。
- 宽桌面、窄窗口、深浅色和中英文下均无内容重叠、截断或页面级横向滚动。
- 正常索引状态不干扰日常分析，异常状态仍可进入系统诊断。
- 前端测试、构建和 Go 测试通过。
