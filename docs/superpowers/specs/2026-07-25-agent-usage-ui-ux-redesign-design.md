# Agent Usage UI/UX 重构设计

日期：2026-07-25  
状态：待评审设计稿  
范围：React/Tauri 桌面端的导航、Overview、Sessions、System、图表和交互层

## 1. 目标与非目标

### 目标

- 让使用者在 10 秒内回答四个问题：花了多少、用在何处、什么时候发生、哪些会话推动了变化。
- 将日常使用信息与索引、定价覆盖率、采集器、诊断信息分离。
- 让会话记录像可阅读的对话复盘，而不是原始 JSONL 日志。
- 在高峰用量合法且真实的前提下，提升历史趋势的可读性，不丢失真实量级。
- 建立可复用的视觉与交互规则，避免页面继续局部堆叠和滚动失控。

### 非目标

- 本轮不改变 token 语义、计费公式、采集器扫描协议或已有 REST 路径的基本含义。
- 不删除原始事件、原始价格或索引元数据；只改变默认呈现层级。
- 不把高峰数据判定为错误或异常。统一使用“峰值”“高峰时段”“高用量”。

## 2. 现状归因

### 信息架构混杂

当前 Dashboard 同时展示使用摘要、采集索引状态、价格覆盖率和本地吞吐；Settings 又混合外观、采集器、定价导入、目录、通知和桌面行为。结果是日常页面被技术状态占据，设置页面变成长列表，用户无法建立“我现在在解决什么问题”的上下文。

### 视觉系统缺乏层级

现有样式以橙色为主色、边框和卡片大量重复，缺少明确的主次层级。页面使用固定高度、嵌套滚动区域和弱化的关闭按钮，导致截图中的底部滚动条、内容截断和弹窗退出成本。

### 会话语义没有分层

后端和前端已经有 normalized event kind，但标题和事件展示仍会把 `environment_context`、权限说明、协作模式等注入内容当作普通用户消息；`unknown`、`metadata`、工具入参与正常对话并列展示。前端因此忠实地显示了数据，却没有帮助用户阅读。

### 图表尺度不适配真实分布

吞吐图将 TPM 分量堆叠在绝对坐标轴上，再叠加 RPM；单个高峰会把其它时间段压成接近零的直线。直接全量归一化又会丢失量级判断，因此需要“趋势可读”和“真实值核对”两种显式模式。

### 定价目录动作不完整

现有目录支持搜索和查看，但没有用户级置顶/排序模型，也把大目录放在临时弹窗里。关闭动作尺寸小、上下文弱，滚动和焦点管理容易让用户迷失。

## 3. 信息架构

采用方向 A：三个一级工作区，System 下设侧边子导航。

```text
Overview
  - 日常使用摘要、趋势、项目/模型归因、最近高用量会话
Sessions
  - 可读会话列表、会话时间线、按需技术详情
System
  - Data sources
  - Pricing
  - Index & diagnostics
  - Preferences
```

### 导航规则

- 一级导航固定在应用壳层，当前项有清晰的文字和选中状态。
- System 内使用左侧子导航；每个子页只处理一个职责。
- 正常状态不在 Overview 显示索引、定价覆盖率、文件数量等技术指标。
- 当索引或定价确实影响数据可信度时，Overview 只显示一条可操作的轻量提示，点击后进入 System 对应子页。
- 主题、语言、通知和自动启动不再与采集器和定价混排，归入 Preferences。

## 4. Overview 设计

### 页面层级

1. 页面标题、时间范围、来源筛选、刷新。
2. 摘要带：Estimated cost、Total tokens、Prompts、Cache served；每项可显示相对上一时段的变化。
3. Usage over time：Cost / Tokens / Prompts 分段切换，tooltip 显示原始值和时间。
4. Top projects / Top models：排行条支持点击联动所有面板，并跳转 Sessions 形成筛选条件。
5. Local throughput：默认显示“趋势模式”，展示峰值标签；可切换“真实值”。
6. Recent drivers：最近高用量会话，直接跳转对应会话。

### 内容原则

- 首页只展示使用者可以据此采取行动的指标。
- “缓存命中率”保留，但用“Cache served/缓存服务比例”这类用户可理解的文案，避免只展示内部字段名。
- 项目和模型排行默认只展示前 5 项，提供“查看全部”进入筛选后的 Sessions 或详情视图。
- 空状态要解释下一步，而不是只显示 0。

## 5. 图表缩放设计

### 默认模式：自适应趋势

- 主坐标范围使用当前序列的 P95 或滚动分位数；低位波动保持可见。
- 超过主坐标范围的合法高用量使用“峰值”或“高峰时段”标记，使用虚线/标签表达被压缩的视觉范围。
- 不删除、不截断、不改写原始数据。
- tooltip 同时显示原始 TPM/RPM、当前视图比例和时间；“比例”仅作为视觉辅助，不用于成本或配额判断。

### 真实值模式

- 使用完整绝对坐标，适合核对量级和峰值。
- 模式名称必须明确是“真实值”，不叫“未归一化”这类实现术语。

### 交互与实现边界

- TPM 与 RPM 保持双轴，但图例按单位分组、颜色对比明确。
- 分段控件记住用户最近选择，但不同时间范围切换时仍显示当前模式。
- 后端继续返回完整 `series`；分位数、视觉裁剪和峰值标注在前端图表适配层计算，避免改变 API 语义。
- 若序列为空或样本过少，退回真实值轴并显示“数据不足以计算趋势缩放”。

## 6. Sessions 设计

### 列表

- 标题优先使用真实首条用户请求；过滤环境上下文、权限说明、开发者注入、协作模式等合成消息。
- 标题为空时按项目名、工作目录 basename、会话 ID 依次回退。
- 列表项只保留标题、项目/来源、最近活动、tokens、cost、prompts；覆盖状态只在影响可读性或完整性时出现。
- 搜索框文案为“搜索请求、回复和工具结果”，筛选条件与时间范围在顶部统一管理。

### 时间线

- 默认 `Readable` 模式：用户消息、助手消息、关键错误按轮次展示。
- 连续工具调用合并为一条活动摘要，例如“调用 3 个工具 · 4.2s”，可展开查看工具名、状态和摘要输出。
- reasoning、metadata、unknown、环境上下文默认折叠到“技术详情”，不占用主要阅读流。
- 完整事件模式保留给需要审计或调试的用户，并明确标注“包含系统事件”。

### 技术详情

- 右侧详情抽屉按需打开，而非常驻三栏。
- 抽屉提供明确的关闭按钮、Escape 关闭、焦点回收和移动端全屏回退。
- 原始 JSON 只在用户主动点击“查看原始记录”后加载；代码区域支持复制和水平滚动。
- 索引不完整、源文件缺失、解析器过期等状态集中显示在会话头部的单条提示中，不再给每个事件贴重复标签。

## 7. System 设计

### Data sources

- 每个 collector 使用一行结构：名称、路径、扫描频率、启用开关、支持的覆盖范围。
- 路径编辑使用等宽输入，长路径截断但可通过 tooltip/展开查看。
- 页面修改后只出现底部 sticky action bar：Discard / Save changes；保存成功后说明需要重启本地服务。
- 提供“Scan now”作为即时动作，不与保存混为一键按钮。

### Pricing

- 顶部展示覆盖率、未定价记录数、最近同步时间和价格来源。
- 同步、JSON 导入和目录浏览是独立动作。
- 目录使用独立子页或全高工作区，不使用小尺寸临时弹窗。
- 模型行提供星标按钮；置顶模型进入固定的 Pinned models 区域，支持拖拽或上移/下移排序。
- 置顶属于用户级显示偏好，不改变后端价格源、计费解析或历史数据。

### Index & diagnostics

- 展示索引覆盖状态、最近更新时间、文件统计、解析错误和需要重建的原因。
- 重建是高影响动作，使用独立确认页/确认对话框，明确“不会删除源文件，只重建本地索引”。
- 诊断内容可复制、可展开，默认不暴露给 Overview。

### Preferences

- 主题、语言、通知、每日成本提醒、自动启动集中管理。
- 二元设置使用开关，数值阈值使用数字输入或步进控件；成功/失败状态就地反馈。

## 8. 视觉系统与交互基线

- 采用中性灰作为基础、暖橙作为行动色、青绿色作为健康/完成色；限制橙色面积，避免页面被单一强调色占满。
- 页面区块使用边界、留白和排版建立层级，避免卡片嵌套卡片。
- 桌面端主页面只保留一个主滚动容器；弹层或抽屉内部滚动时锁定背景滚动。
- 所有图标按钮提供 tooltip/aria-label；关闭、刷新、复制、置顶等动作使用熟悉图标。
- 固定工具栏、摘要带和表头尺寸，避免数据加载或状态变化造成布局跳动。
- 颜色不作为唯一状态表达；错误、覆盖不完整和高峰都同时使用文案/图形提示。
- 支持键盘导航、焦点可见、Escape 关闭、`prefers-reduced-motion`。

## 9. 数据与技术契约

### 后端

- 保持现有 usage、throughput、pricing、session API 兼容。
- 新增或扩展会话标题/消息分类时，优先在 collector normalized event 层标记 `visibility` 或等价语义，不让 React 通过字符串猜测所有系统注入内容。
- 标题生成必须有可测试的过滤规则，并保留原始事件定位能力。
- 置顶模型是本地用户偏好，建议存入现有设置存储或独立 `ui_preferences`，不写入 pricing catalog。

### 前端

- 把 Overview 图表选项生成、throughput 缩放计算、会话可读性分组抽成纯函数，先写单元测试再接入组件。
- 路由保持 `/`、`/sessions`、`/settings` 向后兼容；System 可在 `/settings` 下提供子路由，逐步迁移而不破坏书签。
- 目录从 modal 迁移到 route/drawer 时保留 Escape、焦点管理和深链接能力。

## 10. 分阶段实施计划

### Phase 0：基线与回归保护

- 记录当前页面在桌面、窄窗口、深色模式、中英文下的截图和滚动行为。
- 补齐会话标题、事件分类、throughput option 纯函数测试。
- 定义新的文案 key 和视觉 token，避免边改边产生临时颜色。

### Phase 1：应用壳层与视觉基础

- 重做 Layout、一级/二级导航、主滚动容器和全局颜色/间距/排版 token。
- 保留旧页面逻辑，先替换壳层和通用控件，降低大面积回归风险。

### Phase 2：Overview 与吞吐图

- 按已确认层级重排 Dashboard。
- 实现趋势/真实值分段控件、P95 自适应缩放、峰值标签和完整 tooltip。
- 项目/模型排行与 Sessions 筛选联动。

### Phase 3：Sessions 可读模式

- 后端补充合成消息过滤和标题规则。
- 前端实现 readable/all events 两种模式、工具活动分组、技术详情抽屉。
- 保留原始记录加载和索引完整性提示。

### Phase 4：System 子导航

- 将 Settings 拆为 Data sources、Pricing、Index & diagnostics、Preferences。
- 目录迁移到独立工作区，加入置顶模型和排序持久化。
- 加入 sticky 保存栏、即时扫描、重建确认和统一状态反馈。

### Phase 5：质量与发布

- 完成中英文、深浅色、窄窗口、键盘和 reduced-motion 验证。
- 跑前端测试、Go 测试和 Tauri 构建前的契约检查。
- 对比基线截图，确认没有滚动条叠加、内容截断或焦点陷阱。

## 11. 验收标准

- Overview 首屏不出现正常状态下的索引文件数、解析异常数、定价覆盖率等技术指标。
- 高峰吞吐不会让主体历史趋势变成直线；真实值模式仍能核对原始量级。
- “峰值/高峰时段”不显示为错误或异常状态。
- 会话列表标题不再默认显示 `environment_context` 或权限说明；普通用户可以只读用户/助手内容完成复盘。
- 工具入参、metadata、unknown 和原始 JSON 默认不打断阅读，并可在技术详情中找回。
- System 页面可在两个导航层级内到达任何配置；定价模型可搜索、置顶、排序，且偏好在重启后保留。
- 关闭目录或详情不需要精确点击小图标；支持明显按钮、Escape 和焦点回收。
- 每个页面只有一个主滚动容器，窄窗口和长数据下无嵌套滚动条遮挡内容。
- 现有 API、历史数据、token 语义和成本计算结果不发生回归。

## 12. 成功指标

- 新用户首次打开 Overview 后，不需要进入 System 就能理解当前周期的成本、Token 和主要项目。
- 会话复盘中，用户看到的第一屏主要由自然语言请求/回复组成，而不是原始 JSON。
- 吞吐图在包含极端高峰的数据集上，低位波动仍可辨认；模式切换后原始值一致。
- 设置任务（修改采集路径、同步价格、重建索引）不需要在长页面中寻找超过一次滚动。
